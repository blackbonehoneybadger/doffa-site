# DOFFA DRAKA — сайт doffa.coffee

Сайт игры **DOFFA DRAKA** — бокового файтинга в Telegram (`@doffadrakabot`) — и
её монеты **DOFF** в сети **TON**. DOFFA DRAKA — главная и единственная игра
проекта; кофейня DOFFA, из которой всё выросло, остаётся на сайте своей вкладкой.

```
doffa-site/
├── app/          ← сайт (Next.js) — деплой на Vercel
├── db/           ← SQL-схема БД (пользователи, сессии, лояльность)
├── docs/         ← решения и заметки по сайту
└── public/       ← картинки, видео, логотип; кадры игры — public/brand/game/
```

Сама игра и её сервер живут в отдельном репозитории — здесь только сайт.

**Вкладка «Игра» (`/game`)** даёт выбор, где играть: бот в Telegram (работает,
ссылка — реферальная ссылка владельца `t.me/doffadrakabot?start=ref_DF-000001`)
или приложение на телефон (в ожидании; кнопки магазинов включаются сами, как
только заданы `NEXT_PUBLIC_APP_IOS_URL` / `NEXT_PUBLIC_APP_ANDROID_URL`). Старый
адрес `/download` навсегда перенаправляется на `/game`.

Модель экономики: **Тап → зёрна → драка → DOFF**.
Зёрна — внутренняя игровая энергия (не монета), **DOFF** — монета игры в сети
**TON**, стандарт TEP-74 Jetton, эмиссия 1 000 000 000, выпущена 15.09.2026.
Право допечатки на 28.09.2026 ещё не снято (в сети `mintable: true`), и сайт
говорит это прямо; страница прозрачности читает это поле из сети сама.

Вход в личный кабинет — по кошельку TON, через TON Connect.

### Главное свойство экономики

Фонд наград отдаёт в сутки не число монет, а **долю самого себя** — одну
тысячную остатка. Отсюда Ф(n) = Ф₀·(1−p)ⁿ > 0 при любом n: фонд не кончается,
а не «надолго хватает». Курс «зёрна → DOFF» пересчитывается раз в сутки
(дневной пул делится на вчерашний спрос), шаг заперт множителем два. Формулы
и таблицы живут в игровом репозитории (`server/emission.mjs`,
`docs/doff-economy.md`); сайт читает остаток фонда прямо из сети.

## Сайт (`/`)

**Стек:** Next.js + TypeScript + Tailwind + Framer Motion  
**Деплой:** Vercel (автоматически при пуше в main)  
**Root Directory в Vercel:** `/` (корень)

```bash
npm install
npm run dev      # http://localhost:3000
```

### Видео на главной (`/admin`)

Владелец заходит на `/admin` по общему паролю и загружает до 10 видео —
сайт каждый день автоматически показывает следующее по кругу. Пока ничего
не загружено, на первом экране крутится живая арена из игры —
`/public/brand/game/arena-roastery.webm`.

**Разовая настройка на Vercel (без этого загрузка не заработает):**
1. Vercel → проект → **Storage** → **Create Database** → **Blob** → подключить к проекту
   (это автоматически добавит переменную `BLOB_READ_WRITE_TOKEN`)
2. **Settings → Environment Variables** — добавить:

| Имя | Описание |
|-----|----------|
| `ADMIN_UPLOAD_PASSWORD` | Пароль для входа на `/admin` (придумай сам) |
| `SESSION_SECRET` | Любая случайная строка для подписи сессии |

Локально для разработки — те же переменные в `.env.local` (не коммитится).

### Личный кабинет (`/profile`)

Вход без пароля — по кошельку **TON** через TON Connect: подключил кошелёк →
кошелёк подписал `ton_proof` → вошёл. Подойдёт любой кошелёк TON (Tonkeeper,
MyTonWallet, Telegram Wallet и другие) — список показывает само окно
подключения. Хранит никнейм и бонусные баллы в Postgres (Neon, через Vercel
Storage). Сессии серверные (таблица `sessions`), код входа одноразовый
(`used_nonces`).

**Как проверяется вход** (`app/lib/ton/proof.ts`, 18 проверок в
`test/tonProof.test.ts`):

1. Код входа — наш, выдан этим сервером и не просрочен.
2. Подпись покрывает **домен сайта**, поэтому подпись со стороннего сайта здесь
   бесполезна, даже будучи настоящей.
3. Подпись свежая (не старше 15 минут) и не из будущего.
4. Сама подпись ed25519 сходится с публичным ключом.
5. **Ключ действительно управляет этим адресом** — сверяется с сетью. Без этого
   шага подпись доказывала бы только владение каким-то ключом, и любой мог бы
   назваться чужим адресом. Сеть не ответила → вход заканчивается отказом.
6. Код одноразовый: повтор отклоняется.

Ключом в базе служит **сырой** адрес (`0:9a1b…`): человекочитаемых форм у одного
адреса несколько (UQ… и EQ… — один и тот же кошелёк), и ключ по ним однажды не
узнал бы вернувшегося человека. Человеку показывается форма `UQ…`.

**Разовая настройка на Vercel:**
1. Vercel → проект → **Storage** → **Create Database** → **Postgres** (Neon) → подключить к проекту
   (это добавит переменную `DATABASE_URL` — либо `POSTGRES_URL`, код читает обе)
2. Применить схему один раз:
   ```bash
   # локально, с DATABASE_URL из шага 1 (Vercel → Storage → .env.local tab)
   npm run migrate
   ```
   Либо вставить содержимое `db/schema.sql` вручную в Vercel → Storage → база → **Query**.

`SESSION_SECRET` (см. выше) используется и здесь — для подписи сессии и
одноразового кода на вход, отдельная переменная не нужна.

## Экосистема

- **DOFF** — Jetton в сети TON (mainnet), монета игры.
- **Зёрна** — внутренняя игровая энергия, не продаётся и монетой не является.
  Потолок эмиссии — 25 000 зёрен в сутки на аккаунт, проверяется до боя.
- **DOFFA DRAKA** — единственная игра: 11 бойцов, 15 арен, турниры, бои с живыми
  соперниками (отдельный репозиторий). Открывается в Telegram, без установки;
  приложение на телефон — в ожидании.

Каждый перевод DOFF навсегда записан в блокчейне TON.

### Переменные окружения игры

Все необязательны: без них действуют значения из `app/config/ecosystem.ts`.

```
NEXT_PUBLIC_GAMES_NAME=DOFFA
NEXT_PUBLIC_PRIMARY_GAME_NAME=DOFFA DRAKA
NEXT_PUBLIC_TELEGRAM_BOT=doffadrakabot
NEXT_PUBLIC_GAME_REFERRAL_CODE=       # перебивает код владельца DF-000001 из ecosystem.ts
NEXT_PUBLIC_GAME_TELEGRAM_URL=        # полностью своя ссылка; перебивает две строки выше
NEXT_PUBLIC_DOFF_MASTER=              # адрес контракта DOFF в TON
NEXT_PUBLIC_DOFF_TREASURY=            # публичный адрес фонда наград
NEXT_PUBLIC_DOFF_COLD_STORAGE=        # пусто → адрес холодного хранения не показывается
NEXT_PUBLIC_POOL_DENOMINATOR=1000     # пул = фонд / это число в сутки
NEXT_PUBLIC_FIGHT_BURN_PERCENT=5
NEXT_PUBLIC_FIGHT_PRIZE_PERCENT=5
NEXT_PUBLIC_WITHDRAW_BURN_PERCENT=1
NEXT_PUBLIC_WITHDRAW_PRIZE_PERCENT=1
NEXT_PUBLIC_DAILY_BEAN_CAP=25000
NEXT_PUBLIC_EXCHANGE_STATUS=          # live | testing | planned | paused
NEXT_PUBLIC_CLAIMS_STATUS=
NEXT_PUBLIC_BURN_STATUS=
NEXT_PUBLIC_DEX_URL=
NEXT_PUBLIC_APP_STATUS=               # planned (по умолчанию) | live
NEXT_PUBLIC_APP_IOS_URL=              # ссылка в App Store, когда приложение выйдет
NEXT_PUBLIC_APP_ANDROID_URL=          # ссылка в Google Play
TONAPI_KEY=                           # НЕ NEXT_PUBLIC: ключ не должен попасть в браузер
```

Приватные ключи в `NEXT_PUBLIC_*` **не хранятся** и не могут: сайт только
читает сеть и ничего не подписывает.
