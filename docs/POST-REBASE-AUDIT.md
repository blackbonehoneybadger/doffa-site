### 🟢 Разрешённые места

| `archive/legacy-doffa-token/src/08-find-key.ts` | архив |
| `test/tokenMigration.test.ts` | тест, проверяющий ОТСУТСТВИЕ старого токена в проде |
| `token/src/burn-legacy.ts` | скрипт сжигания старой эмиссии |

Исторические документы **намеренно не переписаны**. Они описывают прошлое, и
править их задним числом означало бы подделывать запись — тот же принцип, по
которому мы не стали править историю блокчейна.

`token/src/burn-legacy.ts` обязан знать старый mint: без него сжигать нечего.
Тест закрепляет, что это **единственный** скрипт с таким исключением.

### 🟢 `app/config/ecosystem.ts` — контролируемое исключение

Старый mint и кошелёк остались в одном месте активного кода — в блоке
`ECOSYSTEM.legacy`. Причина: Шаг 8 задания требует показать старый токен на
`/token` как deprecated. Умолчать о токене, публично видном в сети, значило бы
попытаться его скрыть.

Ключевое отличие от «активной ссылки»: **ни одно операционное поле на него не
ссылается**. Это проверяется тестом, а не обещанием:

```
ECOSYSTEM.token.mint       → null  (не старый адрес)
ECOSYSTEM.token.deployed   → false
DOFFA_PAYMENT_PUBLIC.mint  → null
DOFFA_PAYMENT_PUBLIC.enabled → false
REAL.mint                  → null
```

### 🔴 Что вычищено из production-кода

| `app/config/ecosystem.ts` | `DEFAULT_MINT` = старый | дефолта нет, `mint` из env или `null` |
| `app/config/merch.ts` | fallback на старый mint | `null`, оплата выключается автоматически |

| `test/merchPayments.test.ts` | старый mint как фикстура | нейтральный `TestMint111…` |

Убраны также `effectiveSupply` и `ECOSYSTEM.reward` — обе величины относились
к старому токену и старой, неутверждённой экономике.

### Наградная модель — draft по умолчанию

Три переменные вместо прежних двух:

```
NEXT_PUBLIC_GAME_REWARD_PERCENT
NEXT_PUBLIC_GAME_BURN_PERCENT
NEXT_PUBLIC_GAME_TREASURY_PERCENT
```

Правила:

- модель включается, только если заданы **все три** и их сумма **ровно 100**;
- любое другое сочетание оставляет `draft: true`, и сайт **не показывает
  никаких процентов** — вместо них честное «экономика не утверждена»;
- молча донормировать проценты нельзя: это исказило бы заявленную экономику.

Проверка вынесена в экспортируемую `validateRewardSplit()` и покрыта тестами,
чтобы её нельзя было обойти незаметно.

Безопасные конфиги при этом **не** игнорируются — отдельно проверено:
`token/.env.example`, `package.json`, `tsconfig.json`, `app/config/ecosystem.ts`.

### Secret scanning в CI

Добавлен `.github/workflows/ci.yml`. Прежде CI не было вовсе.

Работа `secrets` (отдельно от проверок качества — её провал означает другой
класс проблемы):

1. **Gitleaks** по полной истории (`fetch-depth: 0`) — ключ мог быть закоммичен
   и потом удалён, в рабочей копии его уже нет, а в истории он остаётся.
2. **Ключи Solana** — поиск JSON-массивов из 64 чисел.
3. **Seed-фразы** — поиск строк из 12/24 слов подряд.
4. **Файлы-ключи под git** — `.gitignore` не действует на уже отслеживаемые
   файлы, поэтому проверяется отдельно.

### Исправленные ошибки

**Линт: 18 → 0.** Ошибки были в `.claude/skills/**/*.cjs` (служебные
CommonJS-скрипты агентов, используют `require()` по своей природе) и в
`archive/legacy-doffa-token/src/04-burn.ts`. Ни то, ни другое не является
исходниками приложения и в бандл не попадает — добавлены в `globalIgnores`.

чего упало правило «в token-скриптах нет старого токена». Правило уточнено, а
не ослаблено: теперь оно требует, чтобы такой файл был ровно один и назывался
именно `burn-legacy.ts`.
