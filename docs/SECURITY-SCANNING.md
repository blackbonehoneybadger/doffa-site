# Проверки безопасности в CI

В репозитории четыре независимых слоя. Первые два бесплатны и работают сразу;
третий и четвёртый — ИИ-ревьюеры, им нужны ключи API.

| Слой | Что ловит | Стоимость | Ключ |
|---|---|---|---|
| Gitleaks | известные форматы секретов | бесплатно | — |
| Свои проверки | ключи Solana, seed-фразы, файлы-ключи под git | бесплатно | — |
| Claude security review | смысловые уязвимости, логика, поток данных | платно | `ANTHROPIC_API_KEY` |
| Codex Security scan | то же, другой моделью | платно | `OPENAI_API_KEY` |

## Почему два ИИ-ревьюера, а не один

Оба читают код смыслово, а не по шаблонам: находят обход авторизации,
логические дыры, утечки через поток данных — то, чего grep не увидит.

Но у каждой модели свои слепые пятна. Две независимые проверки дают то, чего
не даёт одна: если обе указали на одно место — это почти наверняка настоящая
проблема. Если только одна — повод посмотреть внимательно, но спокойно.

Для этого проекта цена ошибки особенная. Токен с эмиссией 100 000 000 и
необратимые операции: отзыв mint/freeze authority, burn. Их не откатить, а
проект уже терял 1 000 000 DOFFA на одной небрежности с ключом. Второй
ревьюер дешевле последствий.

## Как включить

### 1. Получить ключи

- **Anthropic:** https://console.anthropic.com → API Keys
- **OpenAI:** https://platform.openai.com → API keys

### 2. Добавить в GitHub

Settings → Secrets and variables → **Actions** → New repository secret:

| Имя | Значение |
|---|---|
| `ANTHROPIC_API_KEY` | ключ Anthropic |
| `OPENAI_API_KEY` | ключ OpenAI |

Можно добавить только один — второй джоб просто пропустится.

### 3. Проверить

Открой любой PR. В Checks появятся «Claude security review» и «Codex security
scan». Claude пишет находки комментарием прямо в PR.

## Поведение без ключей

Джоб **пропускается**, а не падает. Это сделано намеренно: красный CI,
который нельзя починить кодом, превращается в шум, а шум учит игнорировать
красное — ровно то, чего в проверках безопасности допускать нельзя.

В логах будет `notice` с указанием, какого секрета не хватает.

## ⚠️ Prompt injection

Ни один из инструментов **не защищён** от prompt injection: в PR можно
положить текст, который попытается управлять ревьюером — например, убедить
его не сообщать о находке.

Поэтому оба джоба запускаются **только для PR из этого репозитория**. PR из
форков пропускаются намеренно — там содержимое пишет посторонний.

Дополнительно стоит включить в Settings → Actions → General:
**Require approval for all external contributors**.

## Стоимость

Оба инструмента тратят токены API на каждый PR. Порядок — центы за обычный
PR, но на большом дифе дороже.

Если станет накладно, разумный компромисс: оставить бесплатные слои на каждый
PR, а ИИ-ревьюеров ограничить, добавив в `on: pull_request` фильтр `paths`:

```yaml
on:
  pull_request:
    paths:
      - 'token/**'      # операции с деньгами
      - 'app/api/**'    # серверные роуты
      - 'app/lib/**'
```

Тогда правки текстов и стилей их не запускают, а код, где ошибка стоит денег,
проверяется всегда.

## Что проверяют бесплатные слои

`.github/workflows/ci.yml`, джоб `secrets`:

1. **Gitleaks** по полной истории — ключ мог быть закоммичен и удалён; в
   рабочей копии его нет, а в истории он остаётся навсегда.
2. **Ключи Solana** — файл, всё содержимое которого массив ровно из 64 чисел
   0..255, плюс такие же массивы, вшитые в исходники.
3. **Seed-фразы** — строки из 12 или 24 слов подряд.
4. **Файлы-ключи под контролем версий** — `.gitignore` не действует на уже
   отслеживаемые файлы, поэтому это проверяется отдельно.

Пункт 4 важнее, чем кажется: маски `.gitignore` закрывают известные имена, а
ключ, названный как угодно иначе, они пропустят. При проверке этой логики
тестовый файл назывался `fake-test-wallet.json` и **под маски не попадал** —
поймала его именно проверка в CI.
