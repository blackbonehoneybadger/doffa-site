## Что разблокирует тест

Одно действие владельца — пополнить devnet-адрес:

1. Открыть https://faucet.solana.com
2. Выбрать сеть **devnet**
3. Вставить адрес: `DGy5i2FXHSzq1HH3tNn5yU4xHgDpkyrFGgVrCV3UtwFx`
4. Получить 1–2 SOL (обычно требуется вход через GitHub)

Либо запустить цикл у себя на компьютере — тогда faucet сработает с домашнего
IP. Команды по порядку:

```bash
cd token
cp .env.example .env          # DOFFA_CLUSTER=devnet уже стоит
npm install
npm run token:keygen          # тестовый ключ, только devnet
npm run token:airdrop
npm run token:check-wallet
npm run token:create
npm run token:account
npm run token:mint
npm run token:verify
npm run token:burn -- 1000
npm run token:verify          # supply уменьшился ровно на 1000
npm run token:revoke          # на devnet без подтверждающей фразы
npm run token:verify          # authority = None
```

Адрес devnet-ключа будет свой — тот, что напечатает `token:keygen`.

## Исправлено по ходу

**Ошибка в обосновании BigInt.** В первой версии комментариев было написано,
что 10¹⁴ базовых единиц выходят за точность double. Это неверно:
`MAX_SAFE_INTEGER` ≈ 9·10¹⁵, и 10¹⁴ помещается с запасом. Тест это поймал.

Настоящие причины использовать BigInt другие, и теперь в коде написаны они:

1. суммы SPL — это `u64` с пределом 1.8·10¹⁹, что действительно за границей
   double;
2. разбор дробей через float копит ошибку — `2.01 * 1e6` даёт
   `2009999.9999999998`;
3. API `@solana/spl-token` принимает `bigint`.

**`target` в `tsconfig.json`: ES2017 → ES2020.** Литералы BigInt требуют
ES2020. Проверено полной сборкой — 29 страниц собираются без ошибок.

**`archive/` исключён из корневого `tsconfig`.** Legacy-скрипты используют
зависимости из `token/node_modules`, и корневой `tsc` спотыкался на них после
переноса.
