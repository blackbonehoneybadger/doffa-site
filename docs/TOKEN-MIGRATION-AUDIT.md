## 2. Находки безопасности

### 2.1 🔴 Защита ключей в `.gitignore` покрывает только одно имя файла

```
✅ token/owner.json        → игнорируется (token/.gitignore)
✅ token/.doffa-mint.json  → игнорируется
❌ owner.json (в корне)    → НЕ игнорируется, попадёт в коммит
❌ token/my-key.json       → НЕ игнорируется, попадёт в коммит
```

Ключ, сохранённый под любым другим именем или не в папке `token/`, будет
закоммичен. Исправляется на Этапе 3 добавлением широких правил
(`*keypair*.json`, `*owner*.json`, `*.key.json`, `id.json`).

`git rev-list --objects --all` по маскам keypair/owner/mint — пусто.
Рабочая папка чистая.

Скрипты читают ключ из файла по `KEYPAIR_PATH`, в репозиторий он не попадает.

## 4. Обратимые и необратимые операции

### Обратимые — можно откатить git-revert или повторным деплоем

| Операция | Откат |
|---|---|
| Правки кода, текстов, локалей | revert коммита |
| Перенос скриптов в `archive/` | git сохраняет историю |
| Изменение env в Vercel | вернуть прежнее значение |
| Любые операции в devnet | тестовая сеть, последствий нет |
| Создание нового mint в mainnet | сам mint останется в сети навсегда, но сайт на него можно не переключать |
| Выпуск 100 000 000 на owner wallet | пока mint authority жива — токены можно сжечь и выпустить заново |

### 🔴 Необратимые — отката не существует

| Операция | Последствие |
|---|---|
| **Отзыв mint authority** (→ None) | допечатать токены нельзя **никогда**, никем |
| **Отзыв freeze authority** (→ None) | заморозить аккаунты нельзя никогда |
| **Burn токенов** | уничтоженное не восстановить |
| **Перевод токенов** на чужой адрес | вернуть может только получатель |
| Публикация mint в mainnet | запись в блокчейне навсегда |
| Потеря ключа от owner wallet | доступ к 100 000 000 теряется — как в июле с фондом наград |

Отзыв полномочий выполняется **только** после отдельного подтверждения фразой
`REVOKE DOFFA AUTHORITIES` и только после того, как выполнены все проверки
Этапа 7.

## 6. Риски, которые нужно решить до mainnet

### 6.1 🔴 В сети окажутся два токена с именем DOFFA

Старый mint `57aAfCu…` останется навсегда: его нельзя удалить, а mint/freeze
authority у него уже отозваны. После миграции в mainnet будут **два** SPL-токена
с одинаковыми name и symbol.

Последствия:
- держатели старого токена остаются с деприкированным активом;
- на 99 000 000 старых токенов сохраняется доступ у владельца ключа
  `6cAtKTM8…` — они могут быть проданы или переведены;
- поисковики, агрегаторы и кошельки могут путать токены;
- анти-скам-эвристики могут пометить новый токен как подделку старого.

Минимизируется тем, что `/token` публикует старый mint как **явно
deprecated** со ссылкой на explorer — это Этап 2, он в задании уже есть.

**Требует решения владельца:** что делать со старыми 99 000 000 —
оставить, сжечь или отправить в чёрную дыру. Сжигание старых токенов
необратимо и выполняется только по отдельному подтверждению.

### 6.2 🟡 Логотип не готов к использованию как token image

Присланный файл — JPEG круглого бейджа «DOFFA Espresso Bar» на тёмном фоне с
фотографическими зёрнами и бликами.

| Требование к token image | Текущий файл |
|---|---|
| квадрат 1:1 (512×512 или 1000×1000) | не квадрат |
| PNG, желательно прозрачный фон | JPEG, фон непрозрачный |
| читаемость в 32×32 в списке кошелька | мелкий текст «Espresso Bar / Since 2021» сольётся |

Нужна квадратная PNG-версия. Подготовлю на Этапе 5.

### 6.3 🔴 Постоянное хранилище метаданных требует аккаунта владельца

Metadata JSON и логотип должны лежать на IPFS или Arweave. Загрузка требует
аккаунта в пиннинг-сервисе (Pinata / NFT.Storage / Irys). Я подготовлю сами
файлы и точный JSON, но **загрузить их может только владелец** — токен
пиннинг-сервиса является секретом и в репозиторий не попадает.

Временный URL Vercel как окончательный `METADATA_URI` использовать нельзя:
проект переедет или домен изменится, и токен останется без логотипа навсегда,
потому что после отзыва authority URI не переписать.

### 6.4 🟡 Devnet-airdrop часто ограничен

Публичный faucet devnet регулярно отдаёт rate-limit. Если airdrop не пройдёт,
devnet-тест выполняется через https://faucet.solana.com вручную. На результат
это не влияет, но может потребовать участия владельца.

### 6.5 🟡 Ветка основана на неслитом PR #41

`migration/new-doffa-token` создана от головы `claude/unpack-and-push-19kcxu`
(PR #41), а не от `main`. Иначе миграция воскресила бы «DOFFA Defense» и старые
тексты, которые PR #41 уже исправил.

Следствие: PR #41 нужно слить **до** миграционного PR, иначе второй PR будет
содержать оба набора изменений.
