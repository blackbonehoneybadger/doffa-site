## 3. Что пробовали — без результата

Раздел важнее, чем кажется: он экономит время тому, кто продолжит.

### 🔴 Devnet-airdrop — не получен

Публичный faucet Solana отказывает этому окружению:

```
"You've either reached your airdrop limit today or the airdrop faucet has run dry"
```

Что перепробовано:

| Попытка | Результат |
|---|---|
| `requestAirdrop` через `api.devnet.solana.com` | Internal error |
| 4 повтора с нарастающей паузой (5/10/15 с) | тот же отказ |
| `rpc.ankr.com/solana_devnet` | пустой ответ |
| `solana-test-validator` как локальная цепочка | CLI в контейнере не установлен |

**Вывод:** обойти из этого окружения нечем. Нужен либо пополненный вручную
адрес, либо запуск с домашнего IP.

Адрес devnet-кошелька: `DGy5i2FXHSzq1HH3tNn5yU4xHgDpkyrFGgVrCV3UtwFx` — на
2026-07-31 баланс **0 SOL**.

### ⚠️ Выдуманный API-ключ RPC — ошибка, так делать нельзя

При переборе альтернативных узлов был подставлен несуществующий ключ Helius.
Это неправильно: выдуманные креды не работают и создают ложное впечатление,
что вариант проверен.

**Правило на будущее:** не подставлять придуманные ключи. Если узел требует
аутентификации — это блокер, о нём надо сообщить.

### ⚠️ Неверное обоснование BigInt — исправлено

В комментариях было написано, что 10¹⁴ базовых единиц выходят за точность
double. **Это неверно:** `MAX_SAFE_INTEGER` ≈ 9·10¹⁵, и 10¹⁴ помещается с
запасом. Поймал собственный тест.

Настоящие причины, теперь записанные в коде:

1. суммы SPL — это `u64` с пределом 1.8·10¹⁹, вот он за границей double;
2. разбор дробей через float копит ошибку: `2.01 * 1e6` = `2009999.9999999998`;
3. API `@solana/spl-token` принимает `bigint`.

### ⚠️ Первый прогон secret scanning упал — исправлено

Две причины:

1. **Права.** gitleaks запрашивает `GET /repos/.../pulls/N/commits`, а workflow
   выдавал только `contents: read`. Ответ 403, заголовок назвал нужное:
   `pull_requests=read`.
2. **Ложное срабатывание.** Grep по «64 числа подряд» ловил
   `.claude/skills/ui-styling/scripts/tests/coverage-ui.json` — там числовой
   массив покрытия тестов.

Проверка переписана: настоящий keypair — это файл, **всё содержимое** которого
массив ровно из 64 чисел 0..255. Проверено в обе стороны: 309 файлов чисто,
подложенный настоящий ключ ловится.

Побочная находка: тестовый файл назывался `fake-test-wallet.json` и **под маски
`.gitignore` не попадал**. Маски закрывают известные имена, проверка в CI —
любые. Оба слоя нужны.

### 🔴 Ключ от чёрной дыры `Hk6X6qb…` — не найден, поиск закрыт

1 000 000 старых DOFFA недоступны. Что проверено:

| Где | Результат |
|---|---|
| Файлы на дисках (`npm run legacy:find-key`) | нет |
| История git, включая удалённые файлы | нет |
| Phantom, все аккаунты и производные от seed | нет |
| Переменные Railway старого бота | нет |

Признан утраченным 2026-07-29. **Повторять поиск не нужно.** Адрес объявлен
чёрной дырой проекта.

Важная деталь для формулировок: адрес лежит **на кривой ed25519**, значит ключ
математически существует — просто им никто не владеет. Это не то же самое, что
канонический инсинератор `1nc1nerator111…`, у которого ключа нет в принципе.
Писать «ключа не существует» нельзя — проверяется публично.

## 6. Правила, которые нельзя нарушать

1. **Приватный ключ не покидает компьютер владельца.** Не в `.env`, не в
   GitHub Secrets, не в Vercel, не в чат. Никто не должен его просить.
2. **Mainnet не подписывается из удалённого контейнера.** Сессии ассистента
   эфемерны и живут в облаке.
3. **Необратимое — только по точной фразе** и только после всех проверок.
4. **Не выдумывать данные.** Нет mint — показываем «не создан». Нет метаданных
   — не подставляем временный URL. Нет ключа RPC — это блокер, а не повод
   придумать ключ.
5. **Исторические документы не переписывать.** Они описывают прошлое; правка
   задним числом — подделка записи.
